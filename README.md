# Microbots Arena

Браузерная многопользовательская игра для обучения программированию. Игроки собирают ресурсы, создают микроботов и задают их поведение небольшой программой. Требования: [TODO.md](TODO.md).

## Текущее состояние

Реализованы этапы 1–8: серверная симуляция, экономика, бой, встроенный AI, Canvas, комнаты, лобби, редактор, DSL, победа, перезапуск и UI-полировка. Работает полный цикл от создания комнаты до победы. Задачи прежней передачи Astra Low выполнены; результаты проверки и границы MVP описаны в [HANDOFF.md](HANDOFF.md). По итогам ревью незакрытых задач для Astra Medium в рамках MVP не выявлено.

`AGENTS.md` сохранён без изменений по просьбе пользователя; его сведения о пустых модулях и отсутствующих тестах относятся к исходному scaffold. Актуальные команды находятся ниже и в `package.json` каждого пакета.

## Быстрый запуск

Проверенное окружение: Node.js 24, npm, настольный браузер. Выполните из корня проекта:

```powershell
npm --prefix server ci
npm --prefix frontend/client ci
npm --prefix frontend/client run build
npm --prefix server start
```

Откройте **http://127.0.0.1:3001**. Сервер сам раздаёт собранный клиент. Для остановки нажмите Ctrl+C.

Для разработки запустите в двух терминалах:

```powershell
npm --prefix server run dev
```

```powershell
npm --prefix frontend/client run dev
```

Откройте адрес Vite из терминала (обычно http://localhost:5173). Vite проксирует Socket.IO на `127.0.0.1:3001`.

Для игры в локальной сети запустите собранную версию с `HOST=0.0.0.0`; игроки открывают адрес компьютера хоста. В PowerShell:

```powershell
$env:HOST = '0.0.0.0'
npm --prefix server start
```

`PORT` меняет порт сервера (по умолчанию 3001). При изменении порта в режиме разработки обновите также proxy в `frontend/client/vite.config.js`.

## Как играть

1. Введите имя и нажмите «Создать комнату».
2. Во второй вкладке/браузере введите другое имя и код комнаты, нажмите «Войти».
3. Оба игрока нажимают «Готов», хост — «Начать матч».
4. Каждый получает базу и бота. Сначала ими управляет встроенный AI.
5. Отредактируйте пример слева и нажмите «Применить». Программа назначается всем вашим текущим и будущим ботам. «Включить AI» возвращает встроенное поведение.
6. Для победы уничтожьте базу и всех ботов противника. Потеря только базы ещё не означает поражение.
7. Хост может перезапустить матч; игроки, программы и выбранный режим управления сохраняются, игровые сущности и ресурсы восстанавливаются.

Ошибки компиляции и исполнения отображаются рядом с редактором. «Перейти к строке» выделяет соответствующую строку; если текст уже изменён после применения, сообщение помечается как относящееся к действующей версии. Попадания кратко подсвечиваются белым контуром. Справка использует реальные параметры серверной конфигурации.

До старта можно присоединяться к комнате, после старта — нельзя. Выход или потеря соединения считается поражением; возвращение в начавшийся матч не поддерживается. При выходе хоста права получает следующий участник. Пустая комната удаляется. Если остался один подключённый участник, для новой игры создайте новую комнату. Данные хранятся только в памяти.

## Первая программа

```text
resource = nearestResource()
if resource:
    moveTo(resource)
    collect()
else:
    if random() < 0.05:
        moveTo(random() * 1600, random() * 900)

if canSpawn():
    spawn()
```

Это экономический пример. Готовый пример с боем находится в `server/scripting/example.js` и доступен кнопкой «Пример».

Язык поддерживает числовые выражения, переменные, `if/else` с отступами из пробелов, комментарии `#`, `true/false/null`, `and/or/not`, `+ - * / %`, сравнения `== != < <= > >=`. Переменные создаются заново на каждом тике. Строк, циклов, массивов, доступа к свойствам объектов и произвольного JavaScript нет.

| Bot API | Результат / действие |
| --- | --- |
| `nearestEnemy()`, `nearestResource()`, `nearestFriendly()` | Ближайшая видимая цель или `null`; радиус 250 |
| `moveTo(target)`, `moveTo(x, y)` | Задать цель движения; координаты ограничены картой |
| `attack(target)` | Удар по противнику в радиусе 35 с перезарядкой 500 мс |
| `collect()` | Собрать до 2 единиц ресурса в радиусе 25 за тик |
| `canSpawn()` | Можно ли создать нового бота |
| `spawn()` | Создать бота у своей базы за 30 ресурсов |
| `distance(target)` | Расстояние до цели |
| `random()` | Случайное число от 0 включительно до 1 исключительно |
| `getHealth()`, `getResources()` | HP бота и общий запас ресурсов игрока |
| `getPosition()`, `getBase()` | Текущая позиция и своя база (либо `null`) |

Команды действий возвращают `null`. Проверяйте цель перед её использованием: `if enemy:`. За тик выполняется до 100 операций на бота; тяжёлые запросы поиска стоят дороже. При исчерпании бюджета уже подготовленные действия выполняются, а программа запускается с начала на следующем тике. При ошибке исполнения действия данного бота за этот тик отменяются, его движение прекращается; остальные игроки продолжают играть. Синтаксически неверная новая программа не заменяет действующую.

Ограничения: 8000 символов, 200 строк, 24 уровня вложенности; до 8 игроков и 40 ботов на игрока. Основные игровые параметры собраны в `server/game/config.js`.

## Архитектура

- `server/game/`: состояние, фиксированные тики, движение, экономика, бой и встроенный AI. Не зависит от транспорта.
- `server/scripting/Interpreter.js`: парсер AST и интерпретатор с бюджетом. Нет `eval`, `Function` или исполнения пользовательского Node.js.
- `server/scripting/Api.js`: разрешённые функции и отложенные команды; серверные объекты не выдаются программе.
- `server/network/rooms.js`: комнаты, права хоста, подтверждения команд, рассылка состояния и персональных ошибок.
- `server/app.js`, `server/index.js`: Express, Socket.IO, раздача клиента и запуск.
- `frontend/client/src/App.jsx`: подключение, лобби, состояние интерфейса.
- `frontend/client/src/components/`: Canvas renderer и простой textarea-редактор.

Сервер определяет весь результат игры. Клиент отображает снимки состояния и отправляет команды. Программа одного игрока не передаётся другим.

## Проверки

```powershell
npm --prefix server test
npm --prefix frontend/client run lint
npm --prefix frontend/client run build
npm --prefix server run test:browser
```

28 тестов `node:test` проверяют движение, экономику, бой, полные матчи AI и DSL, интерпретатор, ограничения, комнаты, права хоста, изоляцию и очистку. Браузерная проверка использует два отдельных контекста Playwright: лобби, одинаковое изображение Canvas, Apply, переход к строке ошибки, различение черновика и применённой версии, вёрстку при 1024/1280/1440, появление и исчезновение подсветки попадания, победу в бою, перезапуск и выход. Для ускорения финала она прокручивает настоящие тики симуляции без ожидания реального времени. В тесте выбран одинаковый режим Canvas для точного сравнения пикселей между окнами.

По умолчанию браузерная проверка использует установленный Microsoft Edge в headless-режиме. На машине без Edge:

```powershell
cd server
npx playwright install chromium
$env:BROWSER_CHANNEL = 'chromium'
npm run test:browser
```

Скриншоты сохраняются в `artifacts/match.png`, `artifacts/victory.png` и `artifacts/layout-{1024,1280,1440}.png` (игнорируются Git). Старую демонстрацию движения первого этапа можно запустить через `npm --prefix server run demo`.
