# Запуск и конфигурация

Все команды выполняются из корня репозитория — там, где находятся папки `server` и `frontend`.

Проверенное окружение:

- Node.js 24
- npm
- настольный браузер

---

## Быстрый локальный запуск

Если нужно просто запустить игру на одном компьютере, выполните из корня проекта:

```powershell
npm --prefix server ci
npm --prefix frontend/client ci
npm --prefix frontend/client run build
npm --prefix server start
```

После запуска откройте:

```text
http://127.0.0.1:3001
```

Сервер самостоятельно раздаёт собранный клиент.

Окно терминала должно оставаться открытым во время игры.

Для остановки сервера нажмите:

```text
Ctrl+C
```

Команды `npm ... ci` обычно достаточно выполнить один раз после скачивания проекта или изменения зависимостей.

При последующих запусках достаточно:

```powershell
npm --prefix frontend/client run build
npm --prefix server start
```

Если клиент после последнего запуска не изменялся, можно запускать только:

```powershell
npm --prefix server start
```

## Игра в локальной сети

Если несколько компьютеров находятся в одной локальной сети, сервер запускается только на одном компьютере — компьютере-хосте.

На компьютерах игроков устанавливать Node.js, npm или сам проект не требуется. Им нужен только браузер.

Схема работы:

```text
Компьютер-хост
│
├── Node.js сервер
├── игровой клиент
│
└── 192.168.0.X:3001
        │
        ├── Игрок 1
        ├── Игрок 2
        ├── Игрок 3
        └── ...
```

### Подготовка хоста

Сначала установите зависимости и соберите клиент:

```powershell
npm --prefix server ci
npm --prefix frontend/client ci
npm --prefix frontend/client run build
```

Затем разрешите серверу принимать подключения с других устройств:

```powershell
$env:HOST = '0.0.0.0'
npm --prefix server start
```

После запуска сервер будет доступен не только через `127.0.0.1`, но и через локальный IP компьютера.

---

## Как узнать IP компьютера-хоста

В PowerShell или CMD выполните:

```powershell
ipconfig
```

Найдите используемый сетевой адаптер Ethernet или Wi-Fi и строку:

```text
IPv4 Address . . . . . . . . . . : 192.168.0.100
```

Например, если IP хоста:

```text
192.168.0.100
```

игроки должны открыть:

```text
http://192.168.0.100:3001
```

На клиентских компьютерах больше ничего запускать не требуется.

---

## Рекомендуемый запуск для урока или игры

Для обычной игры через локальную сеть рекомендуется использовать собранную версию клиента.

На хосте:

```powershell
npm --prefix frontend/client run build

$env:HOST = '0.0.0.0'
npm --prefix server start
```

Игроки открывают:

```text
http://IP_ХОСТА:3001
```

Например:

```text
http://192.168.0.100:3001
```

Такой режим проще и стабильнее режима разработки.

---

## Режим разработки

Если необходимо редактировать игру и сразу видеть изменения, сервер и Vite запускаются отдельно.

В первом терминале:

```powershell
npm --prefix server run dev
```

Во втором терминале:

```powershell
npm --prefix frontend/client run dev
```

После этого откройте адрес Vite из терминала, обычно:

```text
http://localhost:5173
```

Vite проксирует Socket.IO и HTTP API на:

```text
127.0.0.1:3001
```

Режим разработки предназначен для изменения кода и тестирования.

Для обычной игры или проведения занятия его использовать не требуется.

## Настройка порта

По умолчанию сервер работает на порту:

```text
3001
```

Порт можно изменить переменной окружения `PORT`.

Например:

```powershell
$env:PORT = '4000'
$env:HOST = '0.0.0.0'

npm --prefix server start
```

После этого игра будет доступна по адресу:

```text
http://127.0.0.1:4000
```

или в локальной сети:

```text
http://IP_ХОСТА:4000
```

Если порт меняется в режиме разработки, необходимо также обновить proxy в:

```text
frontend/client/vite.config.js
```

## Windows Firewall

Если игра открывается на компьютере-хосте, но не открывается на других компьютерах локальной сети, наиболее вероятная причина — Windows Firewall.

Проверить сначала нужно адрес:

```text
http://IP_ХОСТА:3001/health
```

Например:

```text
http://192.168.0.100:3001/health
```

Если он не открывается с другого компьютера, разрешите входящие подключения на порт `3001`.

Запустите PowerShell от имени администратора:

```powershell
New-NetFirewallRule `
    -DisplayName "Microbots Server" `
    -Direction Inbound `
    -Protocol TCP `
    -LocalPort 3001 `
    -Action Allow
```

После этого повторно откройте адрес сервера с клиентского компьютера.

## Диагностика

### Проверка сервера

На компьютере-хосте откройте:

```text
http://127.0.0.1:3001/health
```

Сервер должен вернуть:

```json
{"ok":true}
```

### Проверка из локальной сети

На другом компьютере откройте:

```text
http://IP_ХОСТА:3001/health
```

Например:

```text
http://192.168.0.100:3001/health
```

Если локальная проверка через `127.0.0.1` работает, а проверка с другого компьютера нет, проверьте:

- сервер запущен с `HOST=0.0.0.0`;
- используется правильный IPv4-адрес;
- оба компьютера находятся в одной сети;
- Windows Firewall не блокирует порт `3001`;
- сеть Windows не настроена как изолированная гостевая сеть.

## Конфигурация игры

Игровые параметры находятся в:

```text
server/game/config.js
```

API с текущими игровыми параметрами доступно по адресу:

```text
/api/config
```

Например:

```text
http://127.0.0.1:3001/api/config
```

После изменения конфигурации сервер необходимо перезапустить.

---

## Если сервер просит собрать клиент

Если сервер сообщает, что клиент не собран, выполните:

```powershell
npm --prefix frontend/client run build
```

После этого снова запустите:

```powershell
npm --prefix server start
```

или для локальной сети:

```powershell
$env:HOST = '0.0.0.0'
npm --prefix server start
```

---

## Переменные окружения

Сервер поддерживает:

```text
HOST
PORT
```

Например:

```powershell
$env:HOST = '0.0.0.0'
$env:PORT = '3001'

npm --prefix server start
```

Автоматическая загрузка `.env` в проекте не реализована.

После изменения переменных окружения сервер необходимо перезапустить.

## Остановка сервера

Для обычной остановки нажмите:

```text
Ctrl+C
```

`SIGINT` и `SIGTERM` корректно закрывают подключения и останавливают игровые таймеры.

Все игровые комнаты хранятся только в оперативной памяти.

После остановки процесса сервера:

- комнаты удаляются;
- текущие матчи завершаются;
- подключённые игроки отключаются;
- после нового запуска сервер начинает работу с чистого состояния.

## Быстрый запуск хоста одной командой

Если зависимости уже установлены и клиент собран, для быстрого запуска сервера в локальной сети достаточно вставить в PowerShell:

```powershell
$env:HOST='0.0.0.0'; npm --prefix server start
```

Если нужно сразу пересобрать клиент перед запуском:

```powershell
npm --prefix frontend/client run build; $env:HOST='0.0.0.0'; npm --prefix server start
```

Для первого запуска проекта, когда зависимости ещё не установлены:

```powershell
npm --prefix server ci; npm --prefix frontend/client ci; npm --prefix frontend/client run build; $env:HOST='0.0.0.0'; npm --prefix server start
```

После запуска игроки подключаются по адресу:

```text
http://IP_ХОСТА:3001
```

Например:

```text
http://192.168.0.100:3001
```
